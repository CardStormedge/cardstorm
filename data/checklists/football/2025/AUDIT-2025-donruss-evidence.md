More importantly, this pass adds what the two-source-count system could never answer on its own:

sellers agreeing is real corroboration, but it is not the same *quality* of evidence as
Beckett + TCDB. The counting-error fix is minor; this is the substantive change.

### Source-quality tiers

Every named evidence field is now classified into one of three tiers, based on what the source
actually is (not assumed from a generic label):

- **TIER_A_CHECKLIST** — `checklistInsider`, `beckett`, `footballCardShop`, `tcdb`. Each is either a
  manufacturer-adjacent checklist media writeup or a checklist/rookie-database page that enumerates
  the set directly (footballCardShop's page is a retailer by-set browse listing that itself
  functions as a full checklist enumeration, not a single product's sale listing — kept in Tier A
  per the existing per-source raw files, which already treat it as checklist-equivalent evidence).
- **TIER_B_CARD_DATABASE** — `sportsCardInvestor` (a dedicated card-price-guide site with per-card
  pages) and `priceGuideSite` where the named site is SportsCardsPro (present in every
  `priceGuideSite` record this session, sometimes alongside a bundled Tier-C name like ToyWiz/COMC/
  TradingCardsMarketplace — SportsCardsPro alone justifies Tier B for that field, since it is a
  genuine price-guide/database service, not a marketplace listing).
- **TIER_C_MARKETPLACE** — `marketplaceSearch` (eBay/Mercari — one field regardless of how many
  individual listings/sellers it bundles) and `amazon` (a retail product listing, not a
  price-guide database).
- **Excluded from tier/gate consideration entirely** (as before): `searchSynthesis` (bundled,
  unattributed), `beckettAutographParallel` (non-base subset), and `freshDCards` (documented
  outlier — preserved verbatim, never counted toward any status).

### `_evidenceQualityStatus` (new field, separate from `verificationStatus`)

A record can have `sourceCount:2` (source-count-based `verificationStatus:TWO_SOURCE_VERIFIED`)
while still carrying a *weaker* evidence-quality label if neither of those two sources is Tier A —
that distinction did not exist before this pass. Computed for all 100 records as:

- `CHECKLIST_CROSS_VERIFIED` — 2+ independent Tier A sources
- `CHECKLIST_PLUS_DATABASE` — 1 Tier A + 1 Tier B source
- `DATABASE_CROSS_VERIFIED` — 2+ Tier B sources, no Tier A
- `SINGLE_STRONG_SOURCE` — exactly 1 Tier A or Tier B source, nothing stronger available
- `MARKETPLACE_CORROBORATED` — 2+ Tier C sources only (e.g. eBay + Amazon), no Tier A/B
- `SINGLE_MARKETPLACE_SOURCE` — exactly 1 Tier C source, nothing else
- `REVIEW_REQUIRED` — no individually-attributable named source at all (0 records this pass)

### `_passesStrictProductionGate` (new field — CardStorm's proposed VERIFIED-badge gate)

`PASS` requires **either** 2+ genuinely independent Tier A sources **or** 1 Tier A + 1 independent
Tier B source. Tier C (marketplace) evidence, however many listings, **never** by itself creates a
PASS — Tier C + Tier C and Tier B + Tier C both FAIL this gate, even though both can reach
`TWO_SOURCE_VERIFIED` under the old source-count-only system. This is a proposed initial gate, not
yet implemented in any scanner — `app.html` is untouched (see M/N below).
